# replay-rs v0.3.0-beta.1 — раздельные дорожки, автовыбор кодировщика, плеер и оверлей

Бета-версия с четырьмя крупными функциями для Linux и Windows. На Linux
(KDE Plasma 6, Intel VA-API) они проверены сквозными тестами и вживую; часть
Windows-кода проверена только сборкой и CI, поэтому релиз помечен как
pre-release. Последний стабильный релиз — v0.1.0.

## Что нового

- **Раздельные звуковые дорожки.** Режимы: без звука, только системный,
  только микрофон, смешанный (как раньше) и раздельный — системный звук и
  микрофон двумя независимыми дорожками MP4 (1 — система, 2 — микрофон).
  Индикатор сигнала у каждого источника. Отвалившийся микрофон не
  останавливает запись: дорожка продолжается тишиной, «Повторить» открывает
  его снова. Старые настройки читаются как прежний смешанный режим.
- **Автовыбор кодировщика видео.** Каждый кандидат (VA-API, NVENC, Quick
  Sync, AMF, Media Foundation, Direct3D 12, x264, openh264) проходит пробное
  кодирование; аппаратные раньше программных; если кодировщик падает в
  настоящем конвейере, запись продолжается следующим, и окно показывает
  причину. `replay-rs --list-encoders` — диагностика. HEVC — экспериментально.
- **Встроенный плеер и обрезка.** «Смотреть» в библиотеке: перемотка,
  громкость, выбор дорожки. Обрезка в новый файл: быстрая — без
  перекодирования, с честным показом начала по ключевому кадру; точная — с
  перекодированием, по кадру. Все дорожки сохраняются, оригинал не меняется.
- **Игровой оверлей** (выключен по умолчанию): состояние записи, буфер,
  микрофон, кодировщик, кнопка «Сохранить», итог последнего сохранения.
  Одна строка или карточка, угол экрана, непрозрачность, «всегда» или
  «4 с после сохранения», режим «клики насквозь». Уведомление после
  сохранения и состояние в подсказке трея.
- Клипы пишутся во временный `.part` и появляются в библиотеке только
  целыми; звук перед срезом догоняет видео.

## Готовая сборка

### Linux x86_64

Скачайте `replay-rs-v0.3.0-beta.1-linux-x86_64.tar.gz` и `SHA256SUMS` в один
каталог:

```bash
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf replay-rs-v0.3.0-beta.1-linux-x86_64.tar.gz
cd replay-rs-v0.3.0-beta.1-linux-x86_64
./packaging/install.sh
```

Собрано на Arch Linux с системными библиотеками; на других дистрибутивах
надёжнее собрать из исходников (`cargo build --release --locked`).

### Windows 10 / 11 x86_64

Нужен GStreamer **MSVC x86_64 Runtime**, вариант **Complete** (проверялась
1.26.10). Скачайте `replay-rs-v0.3.0-beta.1-windows-x86_64.zip` и `SHA256SUMS`:

```powershell
(Get-FileHash .\replay-rs-v0.3.0-beta.1-windows-x86_64.zip -Algorithm SHA256).Hash.ToLower()
Get-Content .\SHA256SUMS
Expand-Archive .\replay-rs-v0.3.0-beta.1-windows-x86_64.zip -DestinationPath .\replay-rs
Set-Location .\replay-rs
powershell -NoProfile -ExecutionPolicy Bypass -File .\packaging\install-windows.ps1
```

Для обновления сначала остановите прежнюю версию: `replay-rs --quit`.
Настройки и клипы сохраняются.

## Ограничения

- **Windows:** по умолчанию, как и раньше, программный `x264enc`. Аппаратные
  кодировщики включаются вручную и на оборудовании не проверены; кадр
  подаётся им из системной памяти. Оверлей на Windows проверен только
  сборкой и не виден поверх эксклюзивного полноэкранного режима; масштаб
  DPI не учитывается. Бинарь не подписан (SmartScreen).
- **Оверлей поверх полноэкранной игры не гарантирован:** в GNOME и gamescope
  нет layer-shell — показывается обычным окном; KWin, пока оверлей перекрывает
  полноэкранную игру, отключает для неё прямой вывод (direct scanout).
- NVENC, Quick Sync, AMF, Media Foundation и Direct3D 12 не проверялись ни на
  одной платформе: они выбираются только после пробного кодирования на машине.
- AV1 — только из командной строки (`--video-codec av1`) и только с
  программными кодировщиками.
- Звук плеера идёт на устройство вывода по умолчанию и поэтому попадает в
  системную дорожку фоновой записи.

## Проверка

Linux (Arch, GStreamer 1.28.8, Intel TigerLake VA-API): `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings`, `cargo test --locked` — 96 тестов,
интеграционные тесты с кодированием (`-- --ignored`): звуковые дорожки,
выбор кодировщика, плеер и обрезка, захват, сохранение больших клипов —
успешно; кроме `software_capture`, которому нужен отсутствующий на этой
машине `x264enc`. Нагрузка записи — как у прежней версии (замеры в
`docs/architecture.md`). Windows: сборка, тесты и упаковка в CI; ручной
прогон на Windows 10 и 11 не проводился.
