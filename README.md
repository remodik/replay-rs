# replay-rs

**Сохраняйте последние секунды экрана одним нажатием.**

replay-rs — локальный рекордер с кольцевым буфером для Linux / Wayland (KDE Plasma)
и экспериментальным backend для Windows 10/11. Приложение хранит недавнюю запись в памяти
и по команде сохраняет её в MP4 без повторного кодирования видео.

- Нативное окно: статус записи, заполнение буфера, настройки и библиотека клипов.
- Встроенный плеер и обрезка клипов: быстрая без перекодирования и точная.
- Системный звук и микрофон — одной дорожкой или раздельными, с индикаторами сигнала.
- Автоматический выбор аппаратного кодировщика (VA-API, NVENC, Quick Sync, AMF…) с откатом на программный.
- Игровой оверлей с кнопкой сохранения; уведомления и подсказка в трее.
- Сохранение кнопкой, глобальным сочетанием клавиш, из трея, оверлея или командой.
- Работа без окна и автозапуск при входе в систему.

### Что поддерживается

| Статус | Возможности |
|---|---|
| **Поддерживается** (проверено на Linux, KDE Plasma 6, Intel VA-API) | Кольцевой буфер и MP4 без перекодирования; H.264 через VA-API, openh264; раздельные/смешанная дорожки звука; автовыбор кодировщика и откат; плеер, быстрая и точная обрезка; оверлей через layer-shell |
| **Экспериментально** | HEVC (проверен с vah265enc, vah265lpenc, x265enc; играется не везде); AV1 — только из командной строки (`--video-codec av1`), проверен с программным av1enc |
| **Не проверено на оборудовании** | NVENC, Quick Sync, AMF, Media Foundation, Direct3D 12 — включены в автовыбор, выбираются только после пробного кодирования на машине; весь Windows-оверлей и захват — только сборка и CI |
| **Ограничения платформ** | Оверлей поверх полноэкранной игры не гарантирован: в GNOME и gamescope нет layer-shell (показывается обычным окном), на Windows — не поверх эксклюзивного полноэкранного режима; см. [архитектуру](docs/architecture.md#оверлей) |

## Windows 10 / 11

Добавлен Windows-backend: Direct3D 11, WASAPI, хоткей, трей и установщик
PowerShell. Сборка требует GStreamer MSVC x86_64 и проверяется в CI на Windows;
реальный захват вручную пока не проверен. Windows-сборка выходит как
pre-release v0.2.0-beta.1; Linux-релиз — v0.1.0.

**[Инструкция для Windows: сборка, установка и ограничения](docs/windows.md)**.
Следующие разделы описывают Linux, если не указано иное.

## Требования

Основная целевая среда — **Linux, Wayland и KDE Plasma**. Для других окружений
нужны совместимые реализации порталов ScreenCast и GlobalShortcuts;
работа всех функций в них не гарантируется.

Для сборки и запуска необходимы:

- Rust / Cargo с поддержкой зависимостей из `Cargo.lock`, C-компилятор и `pkg-config`;
- GStreamer с плагинами захвата, H.264, MP4 и обработки звука;
- PipeWire, портал рабочего стола и его backend для вашего окружения;
- хотя бы один кодировщик H.264: VA-API (`vah264enc`), NVENC, Quick Sync
  или программный `x264enc` / `openh264enc` — выбирается автоматически;
- `xdg-open` для открытия файлов и папок; `ffmpeg` / `ffprobe` для диагностики клипов.

Состав пакетов зависит от дистрибутива. В Arch Linux звук AAC предоставляет
`gst-libav`, программный H.264 — `gst-plugins-ugly`; также нужны плагины
GStreamer base/good/bad и PipeWire. Проверьте доступность элементов:

```bash
gst-inspect-1.0 pipewiresrc
gst-inspect-1.0 vah264enc
gst-inspect-1.0 vapostproc
gst-inspect-1.0 mp4mux
gst-inspect-1.0 pulsesrc
gst-inspect-1.0 avenc_aac
```

Отсутствие `avenc_aac` допускается, если доступен `opusenc`. Для программного
кодирования проверьте `gst-inspect-1.0 x264enc`.

## Установка

В каталоге исходников соберите актуальную версию и установите её для своего
пользователя. Сам скрипт установки не требует root:

```bash
cargo build --release --locked
./packaging/install.sh
```

Скрипт использует уже собранный release-бинарь. После обновления исходников
повторите обе команды, чтобы не установить старую сборку.

По умолчанию бинарь появится в `~/.local/bin/replay-rs`, а ярлык — в меню
приложений. Добавьте `~/.local/bin` в `PATH` или используйте полный путь.

Опционально включите автозапуск без окна:

```bash
./packaging/install.sh --autostart
```

Удаление приложения сохраняет настройки, кеш и записанные клипы:

```bash
./packaging/install.sh --uninstall
```

## Первый запуск

1. Откройте **replay-rs** из меню приложений.
2. Разрешите захват и выберите экран в системном диалоге. Повторное использование
   выбора зависит от поддержки портала и сохранённого разрешения.
3. Убедитесь, что в шапке отображается «Запись идёт» и заполняется буфер.
4. Нажмите **«Сохранить 30 с»**. Готовый клип появится в библиотеке.
5. В разделе **«Хоткей сохранения»** нажмите **«Настроить комбинацию…»**
   и назначьте сочетание в системном редакторе.

Приложение предлагает `Ctrl+Alt+S`, но активную комбинацию назначает
пользователь через систему. До назначения доступна кнопка сохранения.

## Управление

| Действие                                | Команда                          |
|-----------------------------------------|----------------------------------|
| Открыть окно и начать захват            | `replay-rs`                      |
| Запустить без окна                      | `replay-rs --headless`           |
| Сохранить клип из работающего рекордера | `replay-rs --save`               |
| Открыть редактор хоткея                 | `replay-rs --configure-shortcut` |
| Завершить работу рекордера              | `replay-rs --quit`               |
| Проверить кодировщики видео             | `replay-rs --list-encoders`      |
| Посмотреть все параметры                | `replay-rs --help`               |

**Крестик сворачивает окно, запись продолжается.** Верните окно через панель
задач. Для выхода используйте меню трея или `--quit`. В текущей реализации
нет открытия окна из трея или из режима `--headless`: потребуется перезапуск.

Команду `replay-rs --save` можно назначить на сочетание клавиш средствами KDE,
если портал GlobalShortcuts недоступен.

## Настройки и данные

Параметры в окне применяются кнопкой **«Применить»**. **«Отменить»** возвращает
поля к действующим значениям. Настройки ниже доступны без редактирования JSON:

| Параметр                  | По умолчанию       | Назначение                           |
|---------------------------|--------------------|--------------------------------------|
| Длина буфера              | 30 с               | Сколько недавнего видео хранить      |
| Сохранять последние       | 30 с               | Запрашиваемая длина клипа            |
| Лимит видеобуфера         | 300 МиБ            | Ограничение памяти для сжатого видео |
| Битрейт видео             | 15 000 кбит/с      | Качество и размер записи             |
| Частота кадров            | 60                 | Кадров в секунду                     |
| Интервал ключевых кадров  | 1 с                | Границы групп кадров                 |
| Видеокодек                | H.264              | H.264 или HEVC                       |
| Кодировщик                | Автоматически      | Лучший работающий; или ручной выбор из прошедших проверку |
| Режим звука               | только системный   | без звука / системный / микрофон / смешанный / раздельные дорожки |
| Громкость источников      | 1,0 / 1,0          | Отдельно для системного звука и микрофона |
| Аудиокодек                | Auto               | AAC при наличии, иначе Opus          |
| Оверлей                   | выключен           | Угол, одна строка, непрозрачность, «всегда» / «4 с после сохранения», клики насквозь |
| Уведомление о сохранении  | выключено          | Системное уведомление после каждого клипа |
| Папка клипов              | `~/Videos/replays` | Каталог сохранения MP4               |

Память ограничена отдельно от длительности: при высоком битрейте в буфере
может быть меньше секунд, чем задано. Клип начинается с ключевого кадра,
поэтому его длина может отличаться от запрошенной. Изменение качества видео
или звуковых параметров перезапускает конвейер записи.

В смешанном режиме системный звук и микрофон сводятся в одну дорожку (так
работали прежние версии, и старые конфиги читаются именно так). В раздельном
— это две независимые дорожки MP4: 1 — системный звук, 2 — микрофон; плееры
обычно играют первую, вторую выбирают в меню дорожек, встроенный плеер
переключает их сам. Рядом с источником показывается, есть ли сигнал;
отвалившийся микрофон не останавливает запись — дорожка продолжается
тишиной, а «Повторить» открывает его снова. При явно выбранном AAC
и недоступном кодировщике приложение предупреждает о переходе на Opus.
Кодек звука перевыбирается при каждой пересборке конвейера.

Кодировщик видео по умолчанию выбирается автоматически: каждый кандидат
проходит пробное кодирование, аппаратные идут раньше программных, а если
выбранный кодировщик падает в настоящем конвейере, запись продолжается
следующим, и окно показывает причину. Ручной выбор и старые значения
конфига (`"Vah264enc"`, `"X264enc"`) сохраняются как есть.

**Библиотека.** «Смотреть» открывает клип во встроенном плеере: перемотка,
громкость, выбор дорожки. Ниже — обрезка: начало и конец, предпросмотр,
«Сохранить фрагмент» в новый файл рядом с оригиналом (оригинал не меняется).
Быстрый режим не перекодирует и начинает с ключевого кадра — окно заранее
показывает фактическое начало; точный перекодирует и режет по кадру.

Флаги командной строки задают параметры текущего запуска поверх сохранённых:

```bash
replay-rs --seconds 60 --save-seconds 20 --fps 60 --output "$HOME/Videos/replays"
replay-rs --encoder x264enc
replay-rs --encoder auto --video-codec h265
```

Если затем нажать «Применить» в окне, текущие параметры сохранятся в конфиг.

### Несколько пользователей одной системы

У каждого пользователя Linux свои настройки, разрешение захвата и каталог
клипов. Устанавливайте и запускайте приложение из собственной графической
сессии. Это локальный рекордер: аккаунтов внутри приложения, совместной
библиотеки и сетевого доступа к клипам нет.

| Данные                | Путь по умолчанию                   |
|-----------------------|-------------------------------------|
| Настройки             | `~/.config/replay-rs/config.json`   |
| Разрешение портала    | `~/.config/replay-rs/restore-token` |
| Превью                | `~/.cache/replay-rs/thumbs/`        |
| Клипы                 | `~/Videos/replays/`                 |
| Блокировка экземпляра | `$XDG_RUNTIME_DIR/replay-rs.pid`    |

Каталоги настроек и кеша учитывают `XDG_CONFIG_HOME` и `XDG_CACHE_HOME`.
Один рекордер работает на один каталог `XDG_RUNTIME_DIR`; обычно он свой
у каждого пользователя. Повторный запуск не создаёт второй захват.
Запуск нескольких сессий одного пользователя с общим runtime-каталогом
не создаёт независимые экземпляры. Без `XDG_RUNTIME_DIR` pid-файл лежит
в личном каталоге кеша (`~/.cache/replay-rs/`), а не в общем `/tmp`.
Pid-файл после аварийного завершения не мешает: `--save` и `--quit` проверяют,
что рекордер действительно жив, и не шлют сигнал по устаревшему pid.

Настройки записываются атомарно: сначала во временный `config.json.tmp`
рядом с конфигом, затем подменой файла. Сбой во время записи оставляет
прежнюю версию настроек целой.

## Решение проблем

| Симптом                                     | Что проверить                                                                                                                                           |
|---------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| Ошибка `vah264enc` / `vapostproc`           | `replay-rs --list-encoders` покажет, какие кодировщики работают и почему нет остальных; поставьте «Кодировщик: Автоматически» |
| Пишется не тем кодировщиком                 | Под списком кодировщиков — причина отката; «Диагностика кодировщиков» в окне                                                                            |
| Микрофон «недоступен»                       | Проверьте устройство записи по умолчанию; «Повторить» рядом с ним откроет его снова                                                                     |
| Оверлей «обычным окном»                     | В композиторе нет layer-shell (GNOME, gamescope): поверх полноэкранной игры он не будет                                                                 |
| Хоткей не сохраняет                         | Назначьте комбинацию в настройках; проверьте `replay-rs --save`                                                                                         |
| Хоткей зарегистрирован у другого приложения | Запускайте установленный replay-rs из меню, а не из встроенного терминала                                                                               |
| Нет звука AAC                               | Проверьте `avenc_aac`; установите пакет с этим элементом или используйте Opus                                                                           |
| Нет превью или клип не открывается          | Проверьте декодер H.264, доступ к файлу и `xdg-open`                                                                                                    |
| «Уже запущен»                               | Найдите окно в панели задач или остановите рекордер через `--quit`                                                                                      |
| «Буфер пуст»                                | Дождитесь начала захвата и проверьте сообщение о состоянии в окне                                                                                       |
| «Ошибка записи»                             | Прочитайте сообщение под статусом, исправьте настройку (например, кодировщик) и нажмите «Применить» — конвейер пересоберётся без перезапуска приложения |

Чтобы заново выбрать экран, остановите рекордер и удалите только токен портала:

```bash
replay-rs --quit
rm -f "${XDG_CONFIG_HOME:-$HOME/.config}/replay-rs/restore-token"
replay-rs
```

Для диагностики запустите приложение из терминала:

```bash
RUST_LOG=debug replay-rs
replay-rs --list-encoders
ffprobe -v error -show_entries stream=index,codec_name,codec_type,duration -of compact clip.mp4
ffmpeg -v error -i clip.mp4 -f null -
```

При сообщении об ошибке приложите шаги воспроизведения, дистрибутив,
версию рабочего окружения, выбранный кодировщик, версию GStreamer и лог.
Перед публикацией проверьте, нет ли в логе личных путей или других приватных данных.

## Разработка

```bash
cargo fmt --all -- --check
cargo check --locked
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
```

Тестовый источник позволяет проверять запись без захвата экрана:

```bash
cargo run -- --mode test --encoder x264enc --seconds 30 --output /tmp/replay-rs-clips
```

Он заменяет видео, но не отключает настроенные источники звука. Для полностью
синтетической проверки используйте интеграционные тесты.

`cargo test` не требует ни кодировщика, ни экрана, ни звука: ему хватает
`appsrc`, `h264parse` и `mp4mux`. Тесты с реальным кодированием помечены
`#[ignore]` и запускаются явно:

| Тест                                                            | Что нужно                                                      |
|-----------------------------------------------------------------|----------------------------------------------------------------|
| `software_capture`                                              | `x264enc`                                                      |
| `service_recovery`, `audio_tracks`, `encoder_selection`, `trim_player` | любой рабочий кодировщик H.264 (автовыбор), AAC или Opus; звуковой сервер не нужен — источники подменены `audiotestsrc` |
| `capture_to_clip`, `restart_timeline`                           | VA-API (`vah264enc`, `vapostproc`)                             |
| `capture_with_audio_produces_two_tracks`, `large_clip_deadlock` | VA-API, звуковой сервер с монитором вывода, AAC или Opus       |

Аппаратные тесты запускайте из своей графической сессии, где доступны
`/dev/dri/renderD*` и PulseAudio/PipeWire. Портал и экран они не трогают:
источник — `videotestsrc`, звук — монитор устройства вывода, файлы пишутся
во временный каталог. Сначала проверьте элементы через `gst-inspect-1.0`,
затем запускайте по одному набору:

```bash
cargo test --locked --test capture_to_clip --test restart_timeline -- --ignored --nocapture
```

```bash
cargo test --locked --test large_clip_deadlock -- --ignored --nocapture
```

Linux CI (`.github/workflows/linux.yml`) проверяет форматирование, clippy,
обычные тесты, release-сборку и `#[ignore]`-тесты на программных
кодировщиках: звуковые дорожки, выбор кодировщика, плеер и обрезку.
Тестов с VA-API и звуком в CI нет: на раннере нет ни GPU, ни звукового сервера.

Основные модули: `src/gui.rs` — интерфейс, `src/player_view.rs` — просмотр и
обрезка в окне, `src/config.rs` — настройки, `src/pipeline.rs` — захват,
`src/encoders.rs` — обнаружение и выбор кодировщика, `src/ringbuf.rs` —
видеобуфер, `src/saver.rs` — сохранение, `src/audio.rs` — звук и индикаторы,
`src/media.rs`, `src/player.rs`, `src/trim.rs` — разбор, плеер и обрезка,
`src/overlay/` — оверлей. Сквозные проверки находятся в `tests/`,
Python-прототип — в `reference/`. Подробности конвейеров и синхронизации
описаны в [архитектурных заметках](docs/architecture.md).

Для вклада в проект опишите решаемую задачу, внесите локальное изменение
и приложите результаты проверок. Отдельно указывайте, проверяли ли вы
настоящий захват через портал или только тестовый источник. Не включайте
в изменения личные конфиги, разрешения портала и записи экрана.
